Research Direction

나는 실제 무인이동체를 스스로 움직이게 만드는 문제를 한다. 전문성은 도구(고전제어 / 강화학습)가 아니라 문제로 정의한다.

학부에서 시작하는 모든 연구는 이 목적에서 출발하고, 아래 로드맵의 칸을 채우면서 끝난다.

큰 방향Unmanned Systems Control — 실제 물리 플랫폼을 움직이는 control + learning
지금 위치3학년 2학기 · 방향을 좁히고 실제 문제 하나를 깊게 파는 구간
좁혀가는 순서학부: 무인이동체 자율제어 → 석사: 해양 무인체 → 논문: 모델 불확실성·외란 하의 Learning-Based Robust Path-Following
정하지 않는 것논문 제목 수준의 좁은 주제. 그건 석사에 들어가면서 좁힌다

로드맵

여섯 칸. 모든 프로젝트·과목·대회는 이 중 하나 이상을 채우려고 시작하고, 채우면 끝난다.

노트 frontmatter에 roadmap: [classical, pipeline] 을 적으면 각 칸의 표에 자동으로 들어온다. 다만 그래프 뷰에 선을 그리는 건 위키링크뿐이다. 그래서 아래 칸마다 링크도 같이 적는다.

1. 파이프라인 pipeline

플랫폼 하나를 센서 → 상태추정 → Planning → Control → Actuator 끝까지.

한 것 Capstone Otter USV · ROS2 USV Term Project · AMET2026 Physicar · Minidrone Workshop 경로추종·회피 LOS Guidance · Pure Pursuit · Stanley Controller · Cross Track Error · Corridor Planner (physicar_planner) 통신·실행환경 DDS

2. 고전제어 기반 classical

깊이를 조절한다. 최우선은 Newton/Euler 동역학 직관 · 좌표계·회전·Quaternion · State-space · Feedback/PID · Lyapunov 안정성 · controllability/observability · 상태추정·Kalman · System Identification · MPC. 후순위는 Robust/Adaptive, 플랫폼별 고급 동역학을 손으로 끝없이 유도하기.

쌓은 것 ANSL Undergraduate Research · 6-DOF Marine Craft Model · Rotation Matrix · Euler Angle Rates · Transport Theorem · Transfer Function · PID Tuning · Anti-windup · Solver Step Size · PWM and Duty Cycle 아직 없는 것 MPC · System Identification · Kalman Filter · State-space · Lyapunov Stability · HILS · Trim Point

3. 학습 기반 learning

순서: Deep Learning → RL → PPO/SAC → Model-based RL → Offline RL → Imitation Learning → Sim-to-Real → Domain Randomization → Safe RL → Learning-based MPC 제어 전공자에게 특히 좋은 자리: Model-based RL / Learning-enhanced MPC / Safe RL.

한 것 DSC Autonomous Driving · Reward Shaping · Multi-armed Bandit · MDP · Extremum Seeking Control 진입 계획 (2026-09-09) 강화학습 — 유닛 14개 + 체크포인트 3개. CP1이 compare 첫 삽, CP3가 hybrid 첫 삽 진도 (2026-09-21) 유닛 0 완료 · S&B 2장 완료 · 유닛 1(3장) 3.1·3.3까지. 다음은 3.5 정책과 가치함수 → Bellman Equation 아직 없는 것 Domain Randomization · Safe RL · Catastrophic Forgetting · PPO · SAC 지도만 그려둔 것 Sim-to-Real — 2026-09-21에 “몇 달 스케일 변화를 RL로 어떻게 다루나”라는 질문에서 나왔다. 학습 전에 쓴 노트라 미검증, 유닛 13에서 자료로 다시 쓴다

4. 같은 문제 두 번 풀기 compare

같은 플랫폼 · 같은 task를 고전으로 한 번, 학습으로 한 번. 지금까지는 플랫폼이 서로 달라서 이 칸이 비어 있다.

무대 확정 (2026-09-27) AUV Control Simulation — 제어공학특론 REMUS 100 AUV를 HoloOcean 위에 강의 모델(MSS remus100.m)과 0.3~0.7 % 로 일치시켜 올리고 Simulink 제어기를 ROS 2 lockstep으로 붙였다. 고전제어 쪽 무대는 준비됨. 학습은 Isaac Lab에서 하고 비교는 이 무대에서 한다 (RL 쪽은 아직 시작 전).

5. 경계 설계 hybrid

RL → desired trajectory + MPC → thruster command, 또는 u = u_MPC + Δu_RL, 또는 RL 명령을 safety filter가 거르는 구조. 이 칸이 채워지는 순간이 내 전문성이 생기는 지점이다. → Learning-based MPC · Residual RL

첫 윤곽 (2026-09-21) Sim-to-Real — 느린 플랜트 변동(선체 오염·계절)을 정책에 맡기지 않고 시간척도로 나누는 것이 이 칸의 설계 원리다. Domain randomization(강인성) + 파라미터 추정(적응) + 하위 적응 제어기(계층) + 주기적 재학습을 같이 쓴다. 미검증 지도.

아이디어 (2026-10-18) 정위치 유지 자세 선택: 정지 임무에서 상위 정책이 해류에 맞춰 선체 자세(pitch·heading)를 고르고, 하위 제어 할당·PID가 그 자세를 유지하는 구조. 이 칸 모양과 같음. 아직 계산 수준이고 중간고사 끝날 때까지 보류

경계 설계 세 갈래 (2026-10-19) 고전제어와 강화학습: 모드별로 RL·모델기반을 섞는 방법은 선택(Switching, 상위는 FSM이어도 됨) · 보완(Residual RL, τ = τ_MB + τ_RL) · 계층 분담(RL guidance + MPC) 세 가지. 모드 배정은 compare 결과로 정당화해야 한다는 게 결론

6. 실물 + 숫자 evidence

“공부했습니다”가 아니라 숫자로 끝나야 한다. 기존 MPC 대비 조류 변화 조건에서 tracking error 32% 감소 / unseen disturbance 성공률 91% / simulation policy를 실제 USV에 이식하여 검증

한 것 Capstone Otter USV(MILS → HILS → 실물) · AMET2026 Physicar(실차 배포) · Minidrone Workshop(코드 생성 → 실기체, 대회 1위)

로드맵에 아직 안 걸린 것

여기 뜨는 노트는 둘 중 하나다. roadmap:을 적는 걸 잊었거나, 방향과 무관한 일을 했거나.

지금 비중

목표는 제어 기반 5060% + learning 4050%. 고전제어를 다 끝낸 다음 RL을 시작하지 않는다 — 병행한다.

두 태그를 다 단 노트는 learning으로 센다. 정확한 수치가 아니라 기울기를 보는 용도.

다음 한 칸

compare 와 hybrid. 가장 가까운 형태는 이거다.

같은 USV heading / path following 을 PID로 만들고 → PPO/SAC로 만들어보고 → RL이 reference나 residual만 내고 PID/MPC가 실제 actuator를 잡는 구조로.

이걸 몇 개만 해보면 “어떤 문제에서 고전제어가 유리하고 어떤 문제에서 learning이 압도적인가”를 논문으로만 배운 사람보다 깊게 알게 된다.

선택 기준

새 과목·프로젝트·대회를 고를 때 던지는 질문 하나.

“이게 경계 설계 능력에 보태지는가?”

  • 플랫폼 전문성은 출발점이지 감옥이 아니다. 좌표계·상태추정·경로추종·actuator saturation·외란·System ID·Sim-to-Real은 플랫폼이 바뀌어도 계속 나온다.
  • 학부에서 가장 가치 있는 건 “전문 분야를 빨리 확정했다”가 아니라, 대학원에 갈 때 ‘나는 이 문제를 왜 연구하고 싶은지’ 설명할 수 있을 만큼 여러 방법을 실제로 써본 것이다.

열린 질문

  • 플랫폼 무게중심을 어디에 둘까. USV/AUV는 조류·파도·바람·모델 오차 때문에 learning의 이유가 강하고 ANSL이 서 있는 자리다. UGV는 AI 전환이 가장 빠르고 데이터·시뮬레이터가 풍부하다. 지금은 둘 다 걸쳐 있음.
  • compare / hybrid 칸을 어느 플랫폼·어느 task에서 채울까. USV heading / path following이 가장 유력.
  • 대학원 진학 / 취업. 근거가 된 대화는 석사 진학을 전제로 흘렀다. 그 전제 자체를 한 번 다시 볼 것.
  • 기체 설계까지 손댈지, 주어진 하드웨어 안에서 제어로만 끌어낼지. 2026-10-18 대화에서 “기존 로봇이 못 하던 기동·임무를 가능하게 하는 연구”(B)에 끌린다는 걸 확인함. 설계까지 가면 Control Co-Design, 아니면 비선형·최적제어·RL → 정위치 유지 자세 선택
  • hybrid 칸을 선택(Controller Selection)으로 채울지, 융합(Controller Integration)으로 채울지. 2026-10-19 대화는 제어 이론 쪽 무게면 융합(Residual RL)부터를 권함. 첫 후보 task는 해류 속 정점유지 → 2026-10-19 계층적 강화학습과 하이브리드 제어
  • Continual / lifelong RL — 흥미롭지만 catastrophic forgetting과 stability-plasticity가 아직 미해결이다. 주제로 잡지 않고 관심으로만 남긴다.
