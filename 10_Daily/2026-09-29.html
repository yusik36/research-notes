2. 모델 구조 — local 과 holo 는 plant 만 다르다

[Constant ×12 + Knob] ref_deg / Kp / Ki / Kd ─Mux─▶ [attitude_pid] ──tau(6)──▶ [plant] ──x(12)──┐
 tau_ff(=tau_trim), tau_max(30), Ts_c ────────────▶        ▲                                     │
                                                           └─────────────────────────────────────┘
localholo
제어기SimulinkSimulink
plantSimulink (Delphin2 MATLAB Function + Integrator, ode4)HoloOcean (HoloOceanPlant → ROS 2 → Python delphin2.py → Unreal 적분·렌더링)
3D 화면없음있음
용도게인 빠르게 맞추기맞춘 게인을 3D 로 확인
  • 상태 x = [u v w p q r x y z φ θ ψ] (Fossen NED), 입력 tau = [X Y Z K M N] (N, N·m) — 구동기 모델 없이 일반화 힘을 직접
  • 제어기 attitude_pid: tau = tau_trim + [0 0 0 PID_φ PID_θ PID_ψ]
    • D 항은 오차 미분이 아니라 body 각속도 p q r → 목표 계단에서 derivative kick 없음 (자세각이 작을 때 φ̇ ≈ p 근사)
    • ψ 오차는 atan2 로 ±180° 감음, K·M·N ±30 N·m 포화 + conditional-integration anti-windup
    • X·Y·Z 는 트림값 고정 → 수심·속도는 제어하지 않음 (그래서 Scope 4단에 z, u 를 띄워 흘러가는 걸 봤음)
  • 설정: FixedStepDiscrete Ts = 0.02 (= 노드 50 Hz), StopTime inf, Simulation Pacing 1x (실시간)
  • PreLoadFcn: Ts, x0(trim_u_10.mat, u = 1 m/s), tau_trim = [7.03621 0 −0.541485 0 −0.543561 0], th_trim_deg ≈ −5.22°

Knob = 모델에 붙은 대시보드 다이얼. Constant 의 Value 에 바인딩돼 있어 시뮬레이션 도는 중에 돌리면 바로 반영된다 (멈추고 더블클릭해서 숫자 고칠 필요 없음). 축×(목표, Kp, Ki, Kd) = 12개.

Selector 블록 (att [10 11 12], KMN [4 5 6], depth_u [9 1]) 은 벡터에서 번호로 골라 Scope 로 보내는 것. Indices 만 바꾸면 다른 상태를 볼 수 있다.

Scope 왼쪽 이름 = 창별 Y축 라벨. 스크립트에서 sc.ActiveDisplay = i; sc.YLabel = ... 로 넣었고, GUI 에선 Configuration Properties → Display → Active display 선택 → Y-label. 범례 이름은 별개로 신호선 이름에서 온다. 축 자동 스케일: sc.AxesScaling = 'Auto' (또는 창에서 Axes scaling → Auto). Auto 는 범위를 넓히기만 할 수 있어서 가끔 Scale 버튼으로 다시 맞춤.

5. 병진(surge·sway·heave)은 왜 입력이 없나

일부러 뺀 것 — 물리적 제약이 아니라 실습 범위를 자세로 좁힌 것. plant 는 tau 6개를 다 받는다. 코드상 tau = [tau_ff(1:3); m] 로 X Y Z 를 트림값에 고정.

  • tau_ff 만 바꾸면 일정한 힘을 미는 개루프가 될 뿐 → 병진 제어를 넣으려면 attitude_pid 코드를 tau_ff(1:3) + 병진 PID 로 고쳐야 한다
  • 보통은 u(전진속도, X), 수심 z(Z 또는 θ cascade)를 제어하고 sway 는 ψ 로 맞춤. 실제 Delphin2 는 이 힘을 추진기·터널 추진기·핀으로 나눠야 함 → 4강 Part 2 (thrust allocation)

8. 지금까지 구현한 범위 — 참값만 쓰고 있다 ⭐

결론: 지금 우리가 만든 건 “Simulink ↔ 시뮬레이터 연동” 과 그 검증까지. IMU 를 포함해 센서 노드는 하나도 없고, 제어기는 DynamicsSensor 가 주는 참값 상태를 받는다. 놓치기 쉬운 7가지 — ① 센서 없음(잡음·지연 0) ② lockstep 이라 시뮬레이터가 제어기를 기다려 줌(실제는 비동기, HoloOceanPlant blocking 은 시뮬 전용) ③ 메시지가 Float64MultiArray(표준 아님) ④ 구동기 없음 ⑤ 환경 비어 있음 ⑥ 검증은 “HoloOcean = MSS 식” 까지, 실기체 대비는 미검증 ⑦ 제어기는 자리표시. 다음 단계 순서: 제어기 설계 → IMU·DVL·수심계 표준 메시지 → EKF → 비동기 실행 → 추진기·할당. → 전체 표와 설명은 현재 구현 범위 — 무엇이 참값이고 무엇이 빠졌나 (2026-09-29 정리) → “놓치고 있는 부분” 보강 (제어 이론과 별개인 환경 구성 관점): 시뮬레이션 환경 현실성 — 특히 ① 수중엔 x·y 를 직접 재는 센서가 거의 없음 ② 노드 tick 50 Hz 라 센서도 최대 50 Hz ③ 좌표 규약이 이미 3개(NED·NWU·ENU) ④ 잡음 0 으로 먼저 연결해 결과가 같은지 보는 순서

θ 목표 Knob 만 연결이 끊김 (local·holo 둘 다)

12개 Knob 중 ref_deg_theta 의 Constant 만 Value 가 숫자가 아니라 변수 th_trim_deg 였다 → Dashboard Knob 은 변수 이름인 파라미터와 연결이 끊긴다. 저장된 바인딩 정보 자체(bdmxdata/BindingPersistence_*.mxarray)는 12개 다 멀쩡했음. 해결: 두 모델의 Value 를 -5.22 로 바꾸고 바인딩 재설정 (MATLAB -batch), 생성 스크립트도 트림 파일에서 숫자로 계산해 넣게 수정, README 에 주의 추가.

Stop 후 다시 Run 하면 60 s 뒤 HoloOceanPlant:timeout

노드는 켜진 동안 k 를 계속 이어가고, Simulink 는 Run 마다 k = 0 부터 센다. 1회차를 k = 1500 에서 멈추면 노드는 “cmd_1500 대기”, 2회차 plant 는 “state_0 대기” → 서로 기다리는 교착. 노드가 state_0 을 1 s 마다 재발행하는 건 맨 처음 k = 0 일 때뿐이었음. → 설계 때 “여러 번 Run” 을 고려 안 한 결함. 리셋 기능으로 해결(결과 7).

리셋 첫 설계의 race condition

처음엔 노드가 리셋을 처리할 때 cmd = None 으로 비웠다. 그런데 첫 실행에선 노드가 1 s 마다 리셋 전 state_0 을 재발행하므로, plant 가 그걸 받고 cmd_0 을 보낸 뒤 노드가 리셋을 처리하면 cmd_0 이 지워져 다시 교착. 수정: 리셋 요청을 콜백에서 받는 순간 이전 cmd 만 지우고(콜백 순서 = 발행 순서라 리셋 뒤 cmd 는 보존), 대기 루프를 “확인 → 대기” 순서로 바꿔 이미 도착한 cmd 를 놓치지 않게 함. 테스트 전에 코드 검토로 잡음.

MATLAB MCP 가 세션에 붙지 않음

failed to attach to MATLAB session → 열린 MATLAB 에서 shareMATLABSession 을 실행해야 붙는다. 그 전엔 .slx 를 zip 으로 풀어 XML 을 읽거나 matlab -batch 로 우회. 테스트 스크립트에서 HoloOceanPlant('SampleTime', ...) 가 실패 → 이름-값 생성자가 없는 System object 라 속성을 따로 대입.
