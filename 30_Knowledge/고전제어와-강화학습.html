고전제어와 강화학습

한 줄로

규칙기반은 사람이 “어떻게 할지” 를 설계하고, 강화학습은 사람이 “무엇이 좋은지” 를 설계한다. 그리고 둘 다 전문분야가 아니라 방법론이다. 전문분야는 문제 쪽에 있다.

왜 필요한가

Research Direction 이 여기서 나왔다. 출발은 “강화학습은 기존 규칙기반 제어랑 아예 다르잖아”라는 질문 하나였고, 가운데에 “고전제어 이론 쌓는 동안 RL이 주가 돼서 경쟁력을 잃는 건 아닐까”라는 걱정이 걸려 있었다. 도착한 자리는 “전문성은 방법론이 아니라 어떤 시스템·문제를 깊게 파봤는가로 정해진다” 였다.

→ 대화 전문: 2026-09-03 강화학습과 규칙기반 제어 비교

결론 여섯 개

1. 설계하는 대상이 다르다

  • 규칙기반: 센서 입력 → 사람이 만든 규칙 → 제어 출력
  • RL: 상태 → 학습된 정책 → 행동 → 결과 → 보상 → 정책 개선

RL도 “사람이 만든 규칙이 없는 방식”은 아니다. state, action, reward, 알고리즘, 네트워크 구조, 안전 제한은 여전히 사람이 설계한다. 달라지는 건 제어 법칙 자체를 사람이 직접 기술하느냐, 경험을 통해 정책으로 학습시키느냐다.

그래서 RL에는 reward hacking이 있다. 에이전트는 설계자의 의도가 아니라 설계자가 정의한 보상을 최대화한다.

2. RL은 물리 지식을 없앤 게 아니라 위치를 옮겼다

에이전트는 동역학을 모르지만 시뮬레이터는 안다.

  • 고전: 인간이 동역학 이해 → 인간이 제어법 설계 → 로봇
  • RL: 물리 시뮬레이터 → 수억 번 경험 → RL이 제어법 탐색 → 로봇

지식과 계산량을 맞바꾼 것. 그래서 RL 이론의 축적량이 역학·제어이론 전체보다 작은 건 당연하고, 그게 약점도 아니다. 대신 대가가 명확하다 — 사전지식을 덜 쓰는 만큼 데이터·시행착오·계산량이 비싸다.

RL 이론은 3층으로 보면 정리된다.

층내용
1층 기반 학문확률·통계·선형대수·최적화·동적계획법·제어이론
2층 RL 이론MDP, value function, Bellman equation, policy optimization, TD learning, exploration, convergence, sample complexity
3층 RL 엔지니어링PPO냐 SAC냐, reward 설계, simulator 구성, observation/action 설계, 학습 속도

로봇에서는 3층이 특히 중요하다. RL 이론을 잘 안다고 보행 로봇이 바로 걷지는 않는다.

3. RL 개발이 답답했던 건 잘못 배워서가 아니다

게인을 바꾸는 건 완성된 제어기의 동작을 바꾸는 것이고, 보상을 바꾸는 건 앞으로 어떤 제어기를 학습할지 목적함수를 바꾸는 것이다. 성격이 다르다.

  • 규칙기반 — 디버깅이 빠르고 국소적: K 변경 → 바로 행동 변경
  • RL — 디버깅이 느리고 전역적: R 변경 → 학습과정 변경 → policy 변화 → 행동 변화

reward를 10% 바꿨다고 행동이 10% 바뀌지 않는다. 항들이 하나의 최적화 문제 안에서 서로 경쟁하기 때문이다. energy penalty를 두 배로 올리면 보폭이 확 줄거나, 이상한 gait가 나오거나, 학습 자체가 불안정해질 수 있다.

reward는 gain이 아니라 평가기준이다. 그래서 실무에서는

  • 이상하면 계수부터 만지지 말고 observation 설계 / action range / termination 조건 / exploration / simulator dynamics 를 먼저 의심한다
  • 총 reward 말고 component별로 로그를 본다. 규칙기반에서 “조향은 좋아졌는데 obstacle distance가 나빠졌네” 하고 보는 것과 같은 역할
  • 풀트레이닝 전에 짧은 학습으로 후보를 거르고, seed를 몇 개 비교한다
  • reward를 바꿔 기존 checkpoint에서 fine-tuning하는 것도 가능하다

→ Reward Shaping

4. 과적합·망각은 “원리적 한계”가 아니다

왼쪽 경사만 오래 학습시키면 정책은 “세상은 항상 왼쪽으로 기울어져 있다”에 최적화된다. 그다음 오른쪽만 학습하면 왼쪽을 잊는데, 이건 과적합이라기보다 catastrophic forgetting이다.

해법은 섞어서 보여주는 것 — 경사·마찰·질량·외란을 매 episode 랜덤화하면 정책이 “왼쪽용 동작”을 외우는 대신 “현재 몸이 어느 방향으로 기울었는지 보고 보정하는 법” 을 배운다. 이것이 Domain Randomization 이 Sim-to-Real 의 핵심 기술인 이유다.

단, 조건이 있다. 로봇이 자기 상태를 관측할 수 있어야 한다. roll angle, angular velocity, 관절 각도·속도, IMU, 발 접촉 상태가 observation에 있어야 왼쪽 경사와 오른쪽 경사가 서로 다른 state로 들어온다.

5. 전환은 ‘대체’가 아니라 ‘침투’다 — AI는 위에서 아래로 내려온다

계층지금앞으로
임무 계획규칙 기반foundation model / AI 증가
행동 결정FSM / 규칙AI·RL 크게 증가
장애물 회피규칙 / 최적화RL 크게 증가
경로 계획A-star, RRTRL 크게 증가
모델 보정System IDonline learning 증가
외란 대응Robust / Adaptivelearning 비중 크게 증가
속도·궤적 추종PID / MPCMPC + learning
자세 안정화PID / LQR / MPC고전 + learning
모터·추력기 제어PID고전제어 강하게 유지

1 kHz로 도는 자세 안정화를 신경망으로 바꿀 유인은 아직 작다. 이미 잘 되고, 계산량이 작고, 안정성을 분석할 수 있으니까. 반면 “저 배가 오른쪽으로 오고 COLREG도 지켜야 하고 파도도 있고 주변에 세 척이 있는데 어떻게 행동할까” 같은 문제는 규칙으로 쓰기가 급격히 어려워진다. RL의 장점이 폭발하는 자리가 거기다.

지금 눈여겨볼 구조는 hybrid다. RL이 desired trajectory → MPC가 thruster command, MPC + NN disturbance estimator, RL 명령을 safety filter가 걸러 안전한 명령으로.

플랫폼별로는 — UGV가 AI 전환이 가장 빠르고, UAV는 planning은 빠르되 inner loop는 오래 고전제어가 남고, USV는 저속·저위험에 모델링 까다로운 외란이 있어 learning의 장점이 잘 드러나고, AUV는 모델 불확실성이 커서 연구적으로 가장 흥미롭지만 실데이터와 Sim-to-Real이 어렵다.

6. 그래서 가치 있는 위치는 ‘경계 설계자’

앞으로 5~10년 제어 분야에서 가장 경쟁력 있는 사람은 고전제어를 가장 많이 외운 사람도, RL 라이브러리를 가장 잘 쓰는 사람도 아니라 둘 사이의 경계를 설계할 수 있는 사람일 가능성이 높다.

AUV가 depth를 못 잡을 때,

  • RL만 아는 사람: reward 0.2 → 0.3 해볼까? learning rate? network 크기?
  • 제어를 아는 사람: buoyancy와 CG/CB 관계? pitch-depth coupling? actuator saturation? observation에 vertical velocity가 빠졌나? thruster allocation의 controllability? delay?

후자는 RL의 search space 자체를 설계해버린다. 이 차이가 크다.

피해야 할 두 극단: “AI가 뜨니까 고전제어는 필요 없다” 와 “AI는 유행이고 진짜 제어는 고전제어다”.

경계를 설계하는 방법은 세 갈래 (2026-10-19 추가)

모드마다 RL이 유리한 곳과 모델기반이 유리한 곳이 있으니, 섞어서 쓰는 구조도 가능하다. 단, 상위 선택기까지 RL일 필요는 없다.

출발점이 된 질문은 이것이다. 모델기반 제어처럼 상위·하위 제어기를 두되, 하위에 임무별로 학습된 모델 여러 개를 넣고 상위가 상황 보고 고르게 할 수 있나?

갈래구조핵심 연구 문제키워드
선택 (Switching)상위가 하위 제어기 중 하나를 고름. 상위는 RL이어도 되고 FSM·Behavior Tree여도 됨언제 전환하나, 전환해도 안정한가(dwell time, Lyapunov). 개별 제어기가 안정해도 전환 시스템 전체는 보장 안 됨HRL, Options (Sutton 1999), Option-Critic (Bacon 2017), Supervisory Control
보완 (Residual)τ = τ_model-based + τ_RL. 기본 성능은 모델기반, RL은 모델에 안 잡힌 외란만 보정RL 보정분의 추력 제한·안정성. RL을 더했다고 안정성이 생기진 않음Residual RL (Johannink 2019)
계층 분담RL이 목표 속도·방향을 내고 MPC가 동역학·제약 지키며 추력 계산RL 결정 능력 + MPC 제약 처리를 같이 쓰기RL + MPPI (AUV 장애물 회피, 2025)

"어떤 제어기를 쓸까(Controller Selection)"와 "어떻게 합칠까(Controller Integration)"는 다른 질문이다. 제어 이론에 무게를 두면 Integration부터 보는 게 RL 역할을 정의하기 쉽다.

  • 임무 중심 HRL(경로추종·회피·정점유지·도킹 중 고르기)은 mission planning 쪽, 같은 임무를 환경별(약한·강한·불규칙 해류)로 나눈 HRL은 adaptive / robust / learning-based control 쪽에 가깝다.
  • “회피는 RL, 정점유지는 MPC가 잘한다”는 가정만으로는 근거가 안 된다. 같은 AUV, 같은 환경에서 둘 다 돌려 비교한 결과가 있어야 모드 배정이 정당화된다. 로드맵 compare → hybrid 순서와 같다.
  • 단순한 임무면 FSM으로 충분하다. 상위 RL을 쓰려면 규칙기반 전환보다 어디서 나은지를 보여야 한다.
  • 대화에서 제안한 순서: ① 해류 속 정점유지 하나로 MPC vs RL 비교 → ② Switching 또는 Residual RL 설계 → ③ 경로추종·회피·자세 전환까지 다중 임무로 확장.

전문성을 어디에 두는가 — 이 대화의 결론

“PID, MPC와 PPO, SAC를 모두 공부했습니다.” → 기술 스택 두 개를 배웠다는 이야기

“모델 불확실성과 외란이 큰 무인이동체의 강인한 제어를 연구했습니다. 정확한 동역학을 얻기 어려운 부분에 learning을 적용하고, 안정성이 중요한 부분에는 model-based control을 결합했습니다. 시뮬레이션 정책을 실제 플랫폼까지 이전하는 Sim-to-Real도 수행했습니다.” → 전문분야

PID와 RL은 전문분야가 아니라 그 문제를 풀기 위해 쓴 도구다.

망치를 잘 쓰는 사람이 아니라, 교량의 진동 문제를 해결하는 사람이고 필요하면 망치도 용접기도 쓰는 사람.

주력 축은 하나 있어도 된다. 전문 문제: 무인이동체 자율제어 안에서 주력: Learning-Based Control + 강한 기반: Dynamics / Classical Control 같은 구조.

헷갈렸던 점

  • “보상만 잘 주면 되던데?” 라는 감각 — 틀린 게 아니다. 로봇 하나를 한 환경에서 걷게 하는 건 현대 RL이 이미 상당히 잘한다. 어려운 건 그다음, 하나의 정책을 계속 살려두면서 새 능력을 계속 얹는 것(continual / lifelong RL)이다.
  • “컴퓨터는 기억력이 좋은데 왜 아기 키우듯 몇 년 학습시키지 않지?” — 아이디어가 혁신적이지 않아서가 아니라 실제로 어려워서 못 푼 쪽에 가깝다. Catastrophic Forgetting, stability-plasticity 문제.
