영상센서처리

한 줄로

픽셀값을 계산으로 바꿔서 영상을 나누고(임곗값), 선명하게 하고(히스토그램 변환), 잡음을 지우고(필터), 경계와 직선을 찾는(에지, 허프) 과목. 중간고사 범위는 1~7주차.

어디에 앉는가: UGV·USV의 카메라 인식 파이프라인 앞단(전처리 → 에지 → 직선/차선 검출). 학습 경로는 Learning Path, AMET 대회의 카메라 corridor planner(Corridor Planner (physicar_planner))가 실제로 이 앞단을 쓴 곳이다.

왜 필요한가

  • 카메라 영상은 그대로 쓰면 조명, 잡음, 낮은 대비 때문에 인식이 흔들린다.
  • 차선 검출 = 그레이 변환 → 블러 → 캐니 → 허프. 이 과목 7주가 그 파이프라인 한 줄이다.
  • 2026-10-19 중간고사 대비로 정리 (손으로 쓰는 서술형 7~8문항).

시험은 “차이, 과정, 특징”을 문장으로 쓰는 것이다

선배 후기 결론: 코딩 문제 없음, 이론만, 주관식 서술.

  • 형식: “A와 B의 차이”, “A를 하는 과정”, “A의 특징”
  • 안 나온 챕터 없음, 1챕터도 출제. 교수가 말로만 한 사소한 것은 안 나옴
  • 26년 1학기: 식은 외우고, 계산 부분은 손으로 풀어 보기, 시험이 어려웠음

"차이" 문제는 같은 기준으로 둘을 나란히 놓아야 점수가 나온다.

디지털화는 위치를 자르고 밝기를 자른다

  • 표본화(sampling): 위치(공간) 를 격자로 나눔 → 해상도
  • 양자화(quantization): 밝기 를 2^b 단계 정수로 → 8비트면 0~255
  • 이진 영상 1비트 / 그레이 8비트 / RGB 24비트. 이 과목에서 “흑백 영상”은 그레이를 뜻한다
  • OpenCV는 BGR, matplotlib은 RGB라서 그대로 출력하면 R과 B가 바뀐다 (교수가 네 번 강조)

샘플링은 위치, 양자화는 밝기.

JPEG는 눈이 둔한 정보부터 버린다

  • 눈은 색보다 밝기에 민감 → 밝기는 지키고 색을 줄인다
  • ① RGB → YCbCr (Y 밝기, Cb = B − Y, Cr = R − Y) ② 크로마 서브샘플링(CbCr 해상도 줄임) ③ DCT로 저주파 유지, 고주파 제거
  • 중요한 정보는 저주파(완만한 밝기 변화)에 몰려 있어서 고주파(머리카락 같은 디테일)를 버려도 티가 안 난다
  • RAW는 헤더가 없어 가로·세로·비트 수를 모른다. BMP 헤더 = 파일 헤더 14B + 정보 헤더 40B, 맨 앞 “BM”(0x42 0x4D)

YCbCr → 크로마 서브샘플링 → DCT, 세 단계 이름까지 쓸 것.

덧셈 오버플로는 saturation으로 막는다

  • saturation: 255 넘으면 255, 0 밑이면 0
  • wrapping: 256으로 나눈 나머지, 0부터 다시 셈. 밝던 곳이 검은 얼룩이 된다
  • wrapping은 영상용으로 만든 기능이 아니라 8비트 저장의 자연스러운 결과(자리올림이 버려짐). 그래서 saturation이 추가 처리다
  • 차이 영상은 단순 뺄셈 대신 절댓값 차

220 + 60 = 280 → saturation 255, wrapping 24.

논리 연산은 흑백 마스크와 함께 쓸 때 의미가 있다

  • 비트 단위 연산. AND = 마스크(검정이 가림), OR = 선택적 세트(흰색이 칠함), XOR = 비교(다른 곳만), NOT = 255 − 값
  • 사진값 x에 대해: x AND 255 = x, x AND 0 = 0, x OR 0 = x, x OR 255 = 255
  • 회색끼리 AND(110 AND 200 = 72)는 눈으로 보면 의미가 없다. 슬라이드 p.8은 “비트 단위로 계산된다”를 보여 주는 계산 연습
  • 픽셀 결합: W·A + (1 − W)·B. 가중치 합이 1이라 밝아지지 않고 섞인다

마스크는 사람이 0과 255로만 만든 영상이다. 사진이 흑백일 필요는 없다.

오츠는 그룹 안이 가장 뭉치는 T를 고른다

  • 클래스 내 분산 최소 = 클래스 간 분산 최대 (같은 말)
  • 분산 = 평균에서 퍼진 정도. 좋은 T로 나누면 어두운 무리끼리, 밝은 무리끼리 뭉친다
  • 개수를 반반으로 나누는 게 아니다. 픽셀값이 확 뛰는 곳(히스토그램 골짜기)에 T가 간다 → 봉우리 2개일 때 가장 효과적
  • 반복 방법(평균만, T를 고쳐 가며 수렴, 종료 기준 T0 필요)과 달리 평균+분산, 반복 없이 한 번에, 정할 값 없음
  • 적응적 임곗값: 블록마다 T. 블록이 너무 작으면 잡음, 너무 크면 전역과 같아짐 (교수: 블록 크기가 가장 중요)

오츠의 "반복 없음"은 후보 256개를 한 번씩 점수 매기는 것이지, 고쳐 가며 수렴하는 게 아니다.

평활화는 등수대로 밝기를 다시 매긴다

  • 누적합 ÷ 전체 픽셀 = “이 밝기 이하가 몇 %” = 등수. 여기에 최대 밝기를 곱하면 등수에 비례한 새 밝기
  • 평평한 히스토그램의 누적 그래프는 직선 → 누적이 직선이 되게 매핑하면 평평해진다 (교수: 가장 핵심 포인트)
  • 스트레칭은 선형으로 폭만 늘림(모양 유지), 평활화는 비선형으로 모양을 평평하게
  • 평활화를 더 많이 쓰는 이유: 파라미터가 없어서 누가 해도 같은 결과 (교수 두 번 강조)
  • End-in: 하위 m%, 상위 n%를 잘라 내고 스트레칭. 잡음 점 하나에 min/max가 휘둘리는 문제 해결

기본 스트레칭은 자르지 않는다. 자르는 건 End-in.

필터는 잡음 종류에 맞춰 고른다

  • 가우시안 잡음(전체가 자글자글) → 평균, 가우시안 / S&P(흰 점·검은 점) → 중간값, 보존 스무딩
  • 가우시안 = 가운데에 큰 가중치를 주는 가중 평균 → 에지를 평균보다 잘 지킴. 파라미터 σ 하나, k = 3σ, 크기 2k+1 (σ=1 → 7×7), 중심값 1/(2π)
  • 분리 가능성: G(x,y) = G(x)·G(y), N² → 2N (7×7: 49 → 14)
  • 중간값: 정렬해서 가운데 값. 튀는 값은 양 끝으로 밀려나 뽑히지 않는다
  • 보존 스무딩: 이웃 8개의 [MIN, MAX]를 벗어날 때만 경계값으로. 튀는 점만 고치고 나머지는 그대로
  • 언샤프: 원본 − 블러 = 에지, 원본 + 에지 = 샤프. 하이부스트 h = (1+α)f − αf̄

블러는 결과물이 아니라 에지를 뽑는 도구다.

1차 미분은 봉우리, 2차 미분은 영교차로 에지를 찾는다

  • 둘 다 에지 검출. 기준만 다르다
  • 그래디언트 방향 ⟂ 에지 (교수: 꼭 기억). 방향은 θ = tan⁻¹(dy/dx) 숫자라 대각선도 표현된다
  • 크기 영상, 방향 영상은 입력과 같은 크기의 2차원 배열로 저장
  • 캐니: 가우시안 → 소벨(크기·방향) → 비최대치 억제(방향 양옆보다 크면 남김, 에지를 얇게) → 히스테리시스(T1 위는 무조건, T1~T2는 강한 에지와 8이웃으로 이어진 것만)
  • 영교차 = 값이 +에서 −로 바뀌며 0을 가로지르는 곳. 그냥 0인 곳은 아니다
  • 라플라시안 0 1 0 / 1 −4 1 / 0 1 0: 마스크 하나로 모든 방향, 대신 잡음에 매우 민감 → 가우시안 먼저(LoG, 멕시칸 모자)

미분해서 0을 지나는 곳은 원래 것의 꼭대기다. f″의 영교차 = f′의 꼭대기 = 에지.

허프 변환은 점들을 지나는 직선의 이름표를 찾는다

  • 직선 y = ax + b는 (a, b) 두 숫자로 정해진다
  • 영상의 점 하나 = 그 점을 지나는 모든 직선 = 파라미터 공간의 직선 하나 (b = −xa + y)
  • 여러 선의 교점 = 그 점들을 모두 지나는 직선. 예: (1,1), (3,3), (−2,−2) → 교점 (1, 0) → y = x
  • 세로선은 a가 무한대 → ρ = x cosθ + y sinθ로 유한하게. θ는 법선 각도(세로선 0°, 가로선 90°)
  • 허프 전에 에지 검출 필수. 임곗값이 크면 정확, 작으면 직선이 많아짐. 확률적 허프는 빠르지만 일부를 놓친다

영상의 직선 하나 = 파라미터 공간의 점 하나, 영상의 점 하나 = 파라미터 공간의 직선 하나.

수식

스트레칭    new = (old − min) / (max − min) × 255
평활화      n[i] = sum[i] / N × I_max          (반올림해서 매핑)
가우시안    G(x,y) = 1/(2πσ²) · exp(−(x²+y²)/(2σ²)),  k = 3σ
하이부스트  h = (1+α)·f − α·f̄
그래디언트  |∇f| = √(dx² + dy²),  θ = tan⁻¹(dy/dx)
라플라시안  ∇²f = f(x+1,y) + f(x−1,y) + f(x,y+1) + f(x,y−1) − 4f(x,y)
허프        b = −x·a + y   /   ρ = x cosθ + y sinθ

읽는 법

  • 스트레칭: 빼서 옮기고(0부터) → 나눠서 0~1로 → 255 곱해서 펼침. 교수가 외우지 말고 세 동작으로 이해하라고 함
  • 평활화: 누적/N은 등수(%), I_max는 범위 최댓값(8비트면 255). 영상에 실제로 있는 최댓값이 아니다
  • 하이부스트: 원본 계수 1+α, 블러 계수 −α. 합이 1이라 밝기 유지

헷갈렸던 점

”saturation과 wrapping은 방식만 다르고 결과는 같다”

255를 넘지 않는 픽셀은 같지만, 넘는 픽셀(원래 밝던 곳)은 wrapping에서 어두운 값(44, 94)이 된다. 오버플로가 난 픽셀에서만 다르다.

”wrapping은 기능을 못 하는데 왜 만들었나”

만든 게 아니라 8비트 덧셈의 자연스러운 결과다. 11111111 + 1에서 9번째 자리가 버려져 0이 된다. 각도·시계처럼 한 바퀴 도는 값에는 오히려 맞다.

”영상에서 0이나 255인 픽셀이 몇 개나 된다고 논리 연산을 하나”

0/255로만 된 건 사진이 아니라 사람이 만든 마스크 쪽이다. 사진값 x AND 255 = x, x AND 0 = 0이라 사진이 회색이어도 깔끔하게 가려진다.

”오츠는 두 그룹의 개수가 비슷해지는 T를 고른다”

틀림. 어두운 것 7개, 밝은 것 2개여도 그 사이를 고른다. 개수가 아니라 그룹 안 밝기가 비슷한지를 본다. 결국 “픽셀값이 확 뛰는 곳”이 있어야 잘 된다는 게 맞는 이해.

”오츠도 T를 여러 번 넣어 보는데 왜 반복이 없다고 하나”

반복 방법은 이번 결과로 다음 T를 고쳐 가며 언제 끝날지 모른다. 오츠는 후보 256개를 한 번씩 점수 매기고 끝. 이진 영상도 매번 만들지 않고 히스토그램 256칸으로만 계산한다.

”언샤프는 흐리게 만든 다음 다시 안 흐리게 만드는 쓸데없는 짓”

흐린 영상은 결과물이 아니라 에지를 뽑는 도구. 원본 − 흐린 영상 = 사라진 디테일 = 에지. 그걸 원본에 더하면 원본보다 선명해진다(되돌리는 게 아님).

“2차 미분은 결국 에지를 얇게 만드는 것”

절반만 맞음. 2차 미분은 에지를 찾는 방법 자체이고(기준이 영교차), 얇은 건 결과로 따라오는 장점. 이미 찾은 에지를 얇게 다듬는 건 캐니의 비최대치 억제다.

”1차 미분도 0을 지나잖아”

맞다. 그런데 f′가 0을 지나는 곳은 f의 꼭대기(흰 띠의 가운데)라 에지가 아니다. 그래서 1차 미분은 봉우리를, 2차 미분은 영교차를 본다.

”허프 공간에서 점은 점으로 나타나는 거 아닌가”

방향이 반대다. 영상의 직선이 허프 공간의 점이고, 영상의 점은 그 점을 지나는 모든 직선을 모은 것이라 허프 공간의 직선이 된다. 아직 완전히 이해 못 함.

”기본 스트레칭은 분포 바깥을 잘라 내고 늘린다”

자르는 건 End-in. 기본 스트레칭은 진짜 minmax를 그대로 0255로 늘린다.
